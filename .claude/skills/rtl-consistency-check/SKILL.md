# فحص اتساق RTL وإمكانية الوصول (RTL & Accessibility Consistency Check)

## الهدف
التأكد من أن كل صفحات HTML في هذا المشروع تتبع نفس القواعد الأساسية للعربية وRTL وإمكانية الوصول، ورصد أي انحراف بين النسخ المكرّرة من CSS في ملفات المحاضرات المختلفة (كل محاضرة تحمل نسخة `<style>` كاملة بداخلها بدل الاعتماد على `assets/site.css`).

## عند الاستخدام
فحص دوري لكل الموقع، أو فحص سريع قبل اعتبار صفحة جديدة جاهزة للنشر.

## الخطوات

1. **اجمعي كل ملفات `.html`** في المشروع (تجاهلي `.git`).
2. لكل ملف، تحققي من:
   - وجود `<!doctype html>` و`<html lang="ar" dir="rtl">`
   - `<meta charset="utf-8">` و`<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`
   - لصفحات هيكل الموقع (index.html على كل المستويات): رابط `assets/site.css` بعدد `../` صحيح حسب عمق المجلد الفعلي للملف
   - لصفحات المحاضرات: وجود كتلة متغيرات الألوان (`:root{...}`) وقاعدة الدارك مود (`@media (prefers-color-scheme: dark)` و`:root[data-theme="dark"]`) داخل `<style>` الصفحة
   - شريط التنقل (`nav.tabs`): breadcrumb كامل يصعد للصفحة الرئيسية، مع `aria-current="page"` على التبويب الحالي فقط (وليس على أي تبويب آخر بالخطأ)
   - كل رسم `<svg>` لشجرة ذهنية يحمل `role="img"` و`aria-label` وصفي
3. **قارني الـ `<style>` بين ملفات المحاضرات** في نفس المادة/المرحلة لرصد أي اختلاف غير مقصود (قاعدة ناقصة، متغير لون محذوف سهوًا، إلخ) قد يكون نتج عن نسخ جزئي عند إنشاء محاضرة جديدة من محاضرة سابقة.
4. **اذكري كل مشكلة بملفها وسطرها التقريبي** مع التصحيح المطلوب، بدون تعديل تلقائي — فقط تقرير، إلا إذا طُلب منك التصحيح مباشرة.
5. إذا لاحظتِ أن تكرار نفس الـ CSS الكامل في كل ملف محاضرة بدأ يصعّب الصيانة (أي تغيير تصميمي يحتاج تعديل كل الملفات)، أشيري إلى ذلك كملاحظة اختيارية (نقل الأنماط المشتركة إلى `assets/site.css` وربطها بدل تكرارها) بدون تنفيذ ذلك من نفسك إلا إذا طُلب صريحًا.
